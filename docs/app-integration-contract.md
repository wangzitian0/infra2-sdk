# App integration contract

This page states how an application runs on the infra2 platform with `infra2-sdk` `v4.10.2`.
The generated tables below come from `data/shared_env.yaml` and `data/stages.yaml`. Regenerate them with `python scripts/render_app_contract.py`.

## 1. Pin one SDK release

- Pin the release wheel URL with its sha256 in the lock file.
- `infra2` accepts an app SDK version inside its declared range after Canary verification.

## 2. Read the environment through the contract

- Read only the canonical names in the table below (`ENVIRONMENT`, not retired names like `ENV`). `infra2_sdk.config.check_shared_env(names)` flags non-canonical names.
- Export your settings manifest with `python -m infra2_sdk.config export module:Settings --json env.manifest.json --markdown env-reference.generated.md --check`.
- Call `infra2_sdk.config.assert_env(manifest)` at startup so missing required variables fail closed.

## 3. Serve standard endpoints and telemetry

- Call `infra2_sdk.service.init_service(app, name, ...)` once to mount `/livez`, `/readyz`, `/health`, request ID middleware (`X-Request-ID`), JSON stdout logs, and OpenTelemetry OTLP export.

## 4. Own your schema and runtime hooks

- Declare a Schema v3 `runtime-hooks.manifest.json` (`infra2_sdk.delivery.RuntimeHooksManifest`) and verify it with `python -m infra2_sdk.delivery check-hooks runtime-hooks.manifest.json`.
- Run pre-deploy PostgreSQL enum and schema verification with `python -m infra2_sdk.storage check-schema`.
